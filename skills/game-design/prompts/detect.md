# 类型分析 → 游戏模式选择（阶段一任务②）

你将看到一部小说的开头部分（约 3000~8000 字）。任务是判断它的类型并选择游戏模式。

## 判断依据（看文本特性，不看题材标签）
1. 多主角平行线 + 史诗跨度 → `epic`
2. 推理/解谜/线索回收是核心 → `puzzle`（含猜谜玩法 riddle 见下）
3. 多势力/编年史/数据密集，情节连续性弱 → `strategy`
4. 章节结构分明（可解析出 ≥3 章）且每章是完整叙事单元，适合"章内分支 + 章末汇聚 + 进度条" → `narrative`（优先于 classic 判断）
5. 单主角连续情节，无强章节结构 → `classic`（默认）

**玩法扩展模式**（按"题材特征触发"，命中即选，优先级高于上述结构判断）：
- 侦探/推理/惊悚悬疑：有真凶/谜底/秘密逐步揭晓 → `puzzle`（线索收集 + 推理提交）
- 恐怖/末日/极端环境/角色有真实生死威胁 → `survival`（数值生命 + 死亡判定）
- 转生/轮回/人生重开（数值转生抽取 + 事件池） → `fate`
- 恋爱浓度高且对白驱动（明确攻略对象 ≥1 + 大量对话场面） → `galgame`
- 文字谜题/猜人物猜章节名（方块遮字、逐字揭示） → `riddle`
- 多主角平行线 + 史诗跨度 → `epic`；多势力/数据密集 → `strategy`

**反默认偏置（防"每本书都做成分支游戏"）**：
- classic 是最后兜底，不是默认项。**输出 classic 前必须逐条否定上述每个特征**，
  并在 rationale 里写明排除链（如"无真凶结构→排除 puzzle；无生死威胁→排除
  survival；无明确攻略对象→排除 galgame"）。
- rationale 只写 2~3 句的"选它"理由不够——必须能看出你认真考虑过别的模式。
- 判断顺序：特性触发 → epic → puzzle → strategy → narrative → classic。
- 模棱两可时选更靠近叙事的模式。

## 主题选择（templates/themes/ 中的 id，12 选 1）

## 分块策略（供下游参考；实际分块为定长切块，模式差异在 extract 阶段体现）
- classic: 按章节/卷分块，保持时间线
- strategy: 按时期/事件阶段分块
- puzzle: 按案件弧线分块
- epic: 按主角线×时期分块
- narrative: 严格按章节边界分块（一章一块，章间只传必要状态）
- galgame: 按角色线/好感度阶段分块
- survival: 按生存阶段/关卡段分块
- riddle: 按谜题组分块
- fate: 按人物群/命运节点分块

  "rationale": "简述选择理由（2~3 句）"
}
