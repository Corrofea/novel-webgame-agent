# 文本处理：清洗 / 章节识别 / 分块

## 输入
- 原始小说文件（TXT / MD / EPUB，EPUB 需安装 ebooklib）
- 已选定的游戏模式 id（决定分块策略，见 `../../templates/game_modes/<id>.json` 的 chunk_strategy）

## 输出
- `runtime/<书>/chapters.json`：`{"chapters": [{"id": 1, "title": "第1章", "text": "..."}]}`
- `runtime/<书>/chunks.json`：`{"chunks": [{"id": "c001", "chapters": [1,2], "text": "...", "mode": "g1_narrative"}]}`

## 流程

### 1. 读取与清洗（脚本 `scripts/chunker.py --ingest`）
- 编码探测：优先 UTF-8，失败尝试 GBK/GB18030（网文 TXT 常见 GBK 乱码）
- 去除：BOM、连续空白行、行首广告残留行（"本章未完"、"手机用户请访问"、"请记住本书首发域名"等模式）
- 去除行尾多余空格与全角空白
- 简体化不做（保留原文）

### 2. 章节识别（脚本，规则为主）
- 匹配模式：`第[零一二三四五六七八九十百千万0-9]+[章节回卷部集]` 或 `Chapter \d+` 或 `楔子/序章/尾声/番外`
- 无章节标记的文本：按自然段落群切分为伪章节（每 ~3000 字一章）
- 每章标题保留原文

### 3. 分块（按模式策略，LLM 辅助做边界判断）
- **G1 叙事冒险**：按章/卷分块，保持时间线顺序；块大小 4000~8000 字
- **G2 策略模拟**：按时期/事件阶段分块（需要 LLM 识别时期边界，调用 `scripts/chunker.py --plan g2` 产出候选边界后由 LLM 确认）
- **S3 解谜探案**：按案件弧线分块（先识别案件起止）
- **S4 多线史诗**：按主角线×时期矩阵分块，块内标注主角线归属
- 超长块（>8000 字）必须再切；连续两个小块（<1000 字）合并

### 4. 质量自检
- 无空块、无重复章节、无乱码行（检测高频替换字符 � 与孤立繁体字混合）
- 清洗前后字数变化 < 30%（异常说明误删内容）
- 输出 chapters.json 与 chunks.json 到 runtime 目录

## 注意事项
- 不要修改正文内容本身（只删噪音），分块边界宁可保守
- 章节标题对后续摘要与场景生成很重要，不要丢弃
- 卷一/卷二的层级信息保留在 chapter 的 `volume` 字段
