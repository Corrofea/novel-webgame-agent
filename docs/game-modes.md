# 游戏模式设计

> 本文档定义「小说类型 → 游戏模式」的映射，是 agent 阶段一"类型分析"任务的判据来源。
> 每种模式对应 `templates/game_modes/<id>.json` 模板。模板是"怎么改编"的骨架，不是改编结果——
> 机制、结构、质量标准是固定的；具体角色、事件、抉择点全部留槽位让 LLM 从小说中提取。
> 所有模式均使用语义化命名（classic / narrative / strategy / puzzle / epic / galgame /
> survival / riddle / fate），不采用早期 G1/G2/S3/S4 编号称呼。

## 分类原则：不看题材标签，看文本特性

小说按"题材"（仙侠/都市/悬疑）分是没有意义的——同样一本悬疑，可以是叙事冒险也可以是解谜游戏。
正确判据是文本的**主导特性**，四个维度依次判断：

| 维度 | 问题 | 命中的模式 |
|---|---|---|
| 强叙事性 | 单主角 + 连续情节线 + 人物关系推动？ | → classic 经典叙事 |
| 强信息量 | 多势力/时间线/数据型内容为主，情节不是核心？ | → strategy 策略模拟 |
| 强逻辑性 | 推理/解谜/伏笔回收是核心，环境与人物影响弱？ | → puzzle 解谜探案 |
| 强综合性 | 多主角平行线 + 史诗跨度 + 名著地位？ | → epic 多线史诗 |

判断顺序：先看是否多主角平行线（epic），再看逻辑核心（puzzle），再看信息量（strategy），
其余落入 classic（默认）。模棱两可时选更靠近叙事的模式——叙事模式对任意文本都能成立，另三种是特化。
再按**玩法特征**检查 5 个扩展模式（galgame/survival/riddle/fate/narrative），特征明显时直接命中。

## 四种基础模式

### classic 经典叙事（默认）
- **适用**：小说、故事、剧本、网文——单主角、情节连续、抉择改变世界线。
- **玩法**：选项分支 + 好感度/属性养成。玩家在剧情节点做选择，影响属性、好感度与后续剧情。
- **文本解构**（extract）：按时间顺序提取**场景单元**（summary 含起因→经过→结果闭环 /
  motivation / characters / location / time / key_event / emotion / atmosphere），
  场景单元即后续场景蓝图的最小素材单位。（参考 insights/1线性故事线整理.md，取中粒度）
- **结局**：3~5 个结局，汇聚到 2~3 个最终结局（防分支爆炸）。
- **界面**：对话/叙述 + 选项按钮 + 属性面板（好感度等）。

### strategy 策略模拟
- **适用**：历史文献、编年史、群像长卷（如《三国演义》式）、数据密集文本。
- **玩法**：策略面板——玩家管理资源/势力数值，在时间线节点做战略决策；成就系统可视化参数变化。
- **文本解构**（extract）：提取**时期表 / 势力表 / 事件表 / 资源维度**（编年史式解构，
  参考 insights/3宏大叙事整理.md 的 chronological 板块简化版）；叙事内容压缩为事件卡片素材。
- **结局**：按势力存亡/数值达标判定多结局。
- **界面**：面板 + 数值图表 + 成就徽章。

### puzzle 解谜探案
- **适用**：侦探、推理、悬疑——线索收集与逻辑推理是核心，微环境受主角决策影响。
  与 riddle（字谜问答）的分界：puzzle 是推理链玩法（线索→推导→提交结论，核心是"选择与推导"），
  riddle 是文字猜谜玩法（核心是"猜专有名词"）。
- **玩法**：对话推进 + 线索收集 + 推理判定。玩家与人物对话获取线索，收集足够线索后做出
  推理结论（可错），错误结论触发不同后果。
- **文本解构**（extract）：提取**案件弧线 / 线索链 / 证词 / 时间线矛盾**
  （每条线索的持有者、指向、解锁条件；谁在说谎的疑点）。
- **结局**：真结局 + 若干错误推理结局。
- **界面**：微型 galgame 对话 + 线索物品栏 + 推理台。

### epic 多线史诗
- **适用**：多主角平行线、史诗名著、家族史诗（如《百年孤独》式）。
- **玩法**：多视角切换（玩家可体验多个主角线）+ 旁批模式——关键节点对比玩家选择与原文选择，
  阐释原文深意与时代背景。
- **文本解构**（extract）：按**主角线 × 时间轴**提取（参考 insights/2非线性叙事整理(1).md 的
  视角切分思路简化）：每条线独立摘要、客观核心事件表（含时间对齐与 uncertainty 标注）、
  闪回/插叙的叙述顺序标记。
- **结局**：每线独立结局 + 全局终局。
- **界面**：视角切换器 + 叙述流 + 旁批侧栏。

## 五个玩法扩展模式

4 个基础模式按"文本主导特性"四维度判定；以下 5 个扩展模式按**具体玩法特征**直接命中
（detect 判断顺序：先看扩展特征，再回落四维度）。

### narrative 章节叙事
- **适用**：任何适合"大章节内自由分支、章节间严格推进"的文本（改造自 classic，叙事更可控）。
- **玩法**：章内分支自由，每章末所有路径汇聚到**章节锚点**（`chapter_end: true` 节点），
  顶部进度条显示"第 X/Y 章"；跨章必须经锚点汇聚（validate 检查回跳）。
- **文本解构**（extract）：每章提取**章轮廓**——2~4 个抉择点、章末悬置（供锚点汇聚）、伏笔点。
- **数据**：节点 `chapter` 字段（章节归属）+ `chapter_end` 锚点 + `mode.chapter_progress.chapters`。
- **QA**：每章至少 1 个锚点；节点缺 chapter 字段告警；跨章直跳告警。

### galgame 恋爱养成
- **适用**：恋爱/日常/群像对白文本，角色好感度是核心驱动力。
- **玩法**：立绘大图 + 底部对话框排版（`mode-galgame` body 类驱动 CSS）；
  好感度门槛（`requires.attrs.affection_x.gte`）触发路线分支；结局收集。
- **文本解构**（extract）：提取**心动场景 / 经典对白（原文原句）/ 路线分歧点**。
- **数据**：`mode.galgame.enabled`；节点用 `speaker` 驱动对白。
- **QA**：好感度门槛可达性（validate 正增量启发式，warning 级）。

### survival 生存试炼
- **适用**：冒险/求生/考验型文本（如穿越无人区、荒野求生）。
- **玩法**：开局**点数分配**（alloc_points 分配到属性）→ 决策消耗/恢复生命值 →
  hp ≤ 阈值自动跳转**死亡场景**（bad 结局）；抵达终点通关。
- **文本解构**（extract）：提取**行程分段 / 资源维度 / 风险抉择（冒险 vs 稳妥的代价收益）/
  绝境死亡素材**。
- **数据**：`mode.survival`（alloc_points/alloc_attrs/hp_attr/death_threshold/death_scene）。
- **QA**：death_scene 必须存在且是结局节点；hp_attr/alloc_attrs 必须已定义。

### riddle 字谜问答
- **适用**：文本有可作谜面的标志性元素（人物名/地名/章节名/道具名），答案是唯一专有名词。
- **玩法**：谜面正常显示，答案**逐字方块遮罩**，玩家单字输入逐步揭示（同字揭示全部
  匹配位置）；全部揭示即通关，goto 继续；提示按钮逐级给出线索。
- **文本解构**（extract）：提取**谜题素材**——可猜对象（人物名/绰号/判词/回目/道具）、
  谜面来源原文（出场描写等）、分层提示（身份类别→原文线索→首字）、线索场景桥段。
- **数据**：节点 `riddle: {question, answer, hints, goto}`；`mode.riddle.enabled`。
- **QA**：riddle 节点必须有 question/answer/goto 且 goto 存在；answer 2~8 字（警告）。

### fate 命运轮回
- **适用**：群像转生/人生重开（人物众多、身份差异大、主题与命运相关）。
- **玩法**：开局**分配命运点数** → 按禀赋（requires 过滤）**随机抽取转生身份** →
  进入该身份剧情线；主线 `fate_event` 标记节点可**随机抽取命运事件**
  （`SCENES.events` 预生成池，未用过且禀赋满足的才可抽）。
- **文本解构**（extract）：提取**转生身份池条目**（名号/描述/禀赋要求/剧情线起点）、
  **独立命运事件**（标题/触发情境/得失际遇/效果方向）、**量化禀赋维度**（原文反复出现的数值要素）。
- **数据**：`mode.fate`（alloc_points/alloc_attrs/draw_pool）+ `SCENES.events` 事件池 +
  节点 `fate_event: true`。纯静态：事件池离线预生成，运行时 `Math.random()` 抽取。
- **QA**：draw_pool ≥ 2 且 start_scene 存在；事件 goto 存在、属性引用合法；入口节点是
  抽取锚点（允许空壳，fate 模式豁免其死路检查）；可达性按入口 ∪ 各身份起点多源 BFS。

## 文本解构（extract 阶段）

每个模式的**特异性文本处理**由管线 extract 阶段落地：逐块调用 LLM，合并为
`runtime/<书>/bible/extract_<mode_id>.json`（`{"mode_id", "items", "failed_blocks"}`），
注入 design 阶段作为场景蓝图的素材库。提取任务与输出 schema 的权威定义在
`templates/game_modes/<id>.json` 的 `extraction` 字段。

| 模式 | 提取单位 | 提取目标（items） | 素材的玩法化去向 |
|---|---|---|---|
| classic | 场景 | 场景单元（summary/motivation/characters/location/time/key_event/emotion/atmosphere） | 场景蓝图节点 + 叙述基调 + 配图提示词 |
| strategy | 时期/事件 | 时期表 / 势力表 / 事件表 / 资源维度 | 回合事件卡片、战略博弈对象、attributes 维度 |
| puzzle | 案件弧线 | 案件 / 线索链 / 证词 / 时间线矛盾 | 线索物品栏、询问对象、推理台候选 |
| epic | 视角线×时间轴 | 主角线 / 客观事件表（含 uncertainty）/ 闪回标记 | 多视角线、旁批点、跨线时间对齐 |
| narrative | 章 | 章轮廓（抉择点 / 章末悬置 / 伏笔） | 章内分支、章节锚点、伏笔回收 |
| galgame | 对白场景 | 心动场景 / 经典对白 / 路线分歧 | 好感度抉择、对话框台词、路线门槛 |
| survival | 行程段 | 行程段 / 资源维度 / 风险抉择 / 绝境素材 | 行程 N 段、资源属性、死亡分支 |
| riddle | 谜题组 | 可猜对象 / 谜面原文 / 分层提示 / 线索场景 / 可猜回目 | riddle 节点（question/answer/hints）、线索场景 |
| fate | 人物群×命运节点 | 转生身份池 / 命运事件 / 禀赋维度 | draw_pool、SCENES.events、attributes 禀赋 |

解构原则：**提取不创作**——素材是原文的浓缩与标注（含情绪/氛围等可玩化信号），
分支、选项、数值等玩法设计仍由 design 阶段完成。单块失败降级跳过（failed_blocks 记录），
素材缺失时 design 合理扩展。

> 灵感来源（仅参考，见 insights/）：1线性故事线整理.md（场景单元提取，classic 采用）、
> 2非线性叙事整理(1).md（三板块解构，epic 采用视角/时间线板块）、
> 3宏大叙事整理.md（四维度编年，strategy 采用编年板块）。
> 任务扮演skill.md 需要运行时 LLM 实时生成角色台词，本项目产物是纯静态（LLM 只离线产出数据），
> 故不实现；galgame 模式的离线台词提取（extract 的 dialogues）是其静态近似。

## QA 标准（每模式）

| 模式 | 必查 |
|---|---|
| classic | 所有选项有去向；好感度条件可达；结局从入口可达 |
| strategy | 数值系统自洽（资源获取/消耗守恒）；事件卡片顺序正确 |
| puzzle | 每条线索有来源与用途；真结局线索完备；推理选项有后果 |
| epic | 各视角线独立可玩；时间线无矛盾；旁批点覆盖关键抉择 |
| narrative | 每章有锚点；无跨章直跳；进度条字段完整 |
| galgame | 好感度门槛可达；对话框 speaker 完整 |
| survival | 死亡场景配置完整且是结局；属性引用合法 |
| riddle | 答案契约完整；goto 存在；结局数与配置一致 |
| fate | 转生池 ≥2；事件池 goto/属性合法；入口空壳豁免；多源可达 |

> 具体字段与开槽见 `templates/game_modes/<id>.json`。
