# 游戏模式设计

> 本文档定义「小说类型 → 游戏模式」的映射，是 agent 阶段一"类型分析"任务的判据来源。
> 每种模式对应 `templates/game_modes/<id>.json` 模板。模板是"怎么改编"的骨架，不是改编结果——
> 机制、结构、质量标准是固定的；具体角色、事件、抉择点全部留槽位让 LLM 从小说中提取。

## 分类原则：不看题材标签，看文本特性

小说按"题材"（仙侠/都市/悬疑）分是没有意义的——同样一本悬疑，可以是叙事冒险也可以是解谜游戏。
正确判据是文本的**主导特性**，四个维度依次判断：

| 维度 | 问题 | 命中的模式 |
|---|---|---|
| 强叙事性 | 单主角 + 连续情节线 + 人物关系推动？ | → G1 叙事冒险 |
| 强信息量 | 多势力/时间线/数据型内容为主，情节不是核心？ | → G2 策略模拟 |
| 强逻辑性 | 推理/解谜/伏笔回收是核心，环境与人物影响弱？ | → S3 解谜探案 |
| 强综合性 | 多主角平行线 + 史诗跨度 + 名著地位？ | → S4 多线史诗 |

判断顺序：先看是否多主角平行线（S4），再看逻辑核心（S3），再看信息量（G2），
其余落入 G1（默认）。模棱两可时选更靠近叙事的模式——叙事模式对任意文本都能成立，另三种是特化。

## 四种模式

### G1 叙事冒险（默认）
- **适用**：小说、故事、剧本、网文——单主角、情节连续、抉择改变世界线。
- **玩法**：选项分支 + 好感度/属性养成。玩家在剧情节点做选择，影响属性、好感度与后续剧情。
- **文本解构**：保持章节顺序（时间线即剧情线），按卷/章分块；提取"决策点"展开为分支。
- **结局**：3~5 个结局，汇聚到 2~3 个最终结局（防分支爆炸）。
- **界面**：对话/叙述 + 选项按钮 + 属性面板（好感度等）。

### G2 策略模拟
- **适用**：历史文献、编年史、群像长卷（如《三国演义》式）、数据密集文本。
- **玩法**：策略面板——玩家管理资源/势力数值，在时间线节点做战略决策；成就系统可视化参数变化。
- **文本解构**：按时期/事件阶段分块；从原文提取**结构化数据表**（势力表、事件表、时间线），
  叙事内容压缩为背景条目。剧情卡点做成"事件卡片"。
- **结局**：按势力存亡/数值达标判定多结局。
- **界面**：面板 + 数值图表 + 成就徽章。

### S3 解谜探案
- **适用**：侦探、推理、悬疑——线索收集与逻辑推理是核心，微环境受主角决策影响。
- **玩法**：对话推进 + 线索收集 + 推理判定。玩家与人物对话获取线索，收集足够线索后做出
  推理结论（可错），错误结论触发不同后果。
- **文本解构**：按案件弧线分块；提取**线索链**（每条线索的持有者、指向、解锁条件），
  人物微环境变化影响可获得的对话选项。
- **结局**：真结局 + 若干错误推理结局。
- **界面**：微型 galgame 对话 + 线索物品栏 + 推理台。

### S4 多线史诗
- **适用**：多主角平行线、史诗名著、家族史诗（如《百年孤独》式）。
- **玩法**：多视角切换（玩家可体验多个主角线）+ 旁批模式——关键节点对比玩家选择与原文选择，
  阐释原文深意与时代背景。
- **文本解构**：按**主角线 × 时间轴**矩阵分块；每条线独立摘要，再交叉合并时间线；
  决策点标注"原文选择"供对比。
- **结局**：每线独立结局 + 全局终局。
- **界面**：视角切换器 + 叙述流 + 旁批侧栏。

## 文本解构策略总表

| 模式 | 分块单位 | 保留什么 | 丢弃/压缩什么 | 重建结构 |
|---|---|---|---|---|
| G1 | 章/卷 | 情节连续性、对话、决策点 | 重复描写 | 场景图（scene graph） |
| G2 | 时期/事件段 | 事件、人物行动、数值线索 | 抒情、细碎对话 | 事件卡片 + 数据表 |
| S3 | 案件弧线 | 线索、证词、时间线细节 | 无关生活琐事 | 线索链 + 推理树 |
| S4 | 主角线×时期 | 各线核心事件、角色命运 | 支线重复 | 平行时间线 + 旁批点 |

## QA 标准（每模式）

| 模式 | 必查 |
|---|---|
| G1 | 所有选项有去向；好感度条件可达；结局从入口可达 |
| G2 | 数值系统自洽（资源获取/消耗守恒）；事件卡片顺序正确 |
| S3 | 每条线索有来源与用途；真结局线索完备；推理选项有后果 |
| S4 | 各视角线独立可玩；时间线无矛盾；旁批点覆盖关键抉择 |

> 具体字段与开槽见 `templates/game_modes/<id>.json`。
