# Skill 2：线性故事摘要提取

## 功能描述
将输入的叙事文本（小说章节、传记片段、历史叙事等）按时间顺序提取为结构化情节单元。每个单元不仅包含传统六要素（人物、时间、地点、起因、经过、结果），还额外捕获事件驱动原因（动机）、核心情绪基调和关键氛围描写，使摘要既适合游戏化改编的场景复用，也能保留原作的情感厚度与叙事逻辑。

## 处理原则
严格顺序：绝不改变故事线顺序，不进行重组或分支设计。

场景切分标准：以“时间连续 + 空间稳定 + 冲突/主题完整”为一个独立场景。若时间或空间发生明显跳跃（如次日、不同地点），或核心矛盾发生转变，则切分为新场景。

因果链显性化：每个场景的 motivation 字段明确写出“本场景发生的前因”（可由前文推断或原文明示），summary 中必须包含起因→经过→结果的闭合逻辑。

粒度调节规则：

细粒度：以每个明确的时空单元（如一次对话、一场小事件）为场景，适合逐帧改编。

中粒度（默认）：以若干连续动作组成的一个完整冲突/事件单元为场景（例如从“出发”到“抵达”再到“冲突结束”）。

粗粒度：以整章或完整情节段落（如“疗养院探望全程”）为一个场景，突出大线条。

若未指定，默认为“中粒度”。

情绪与氛围捕获：若原文有大段心理描写或环境烘托，在 atmosphere 字段用一句话概括关键氛围（如“阴雨中的孤独感”），emotion 字段列出该场景主导情绪（如“哀伤/释然/困惑”）。若无显著描写，可为空或默认“中性”。

时间标注精细化：尽可能提取原文明确时间（如“一九六九年秋”、“二十岁生日当晚”），无法精确则标注“故事内相对时间”（如“木月死后第二年”）。

## 输入格式
source_text：原始文本（完整章节或多段）。

options（可选）：

granularity："fine" / "medium" / "coarse"，默认为 "medium"。

focus："full"（全面）、"conflict"（突出冲突）、"emotion"（侧重情绪），默认为 "full"。

include_atmosphere：true / false，是否提取氛围描写，默认为 true。

## 输出格式
输出一个 JSON 数组，每个元素为一个场景块，按原文顺序排列。字段说明如下：

字段	类型	说明
scene_id	string	场景编号，如 "S1"
summary	string	场景概览，必须包含起因、经过、结果的闭环（如：因XX原因，发生了XX，导致XX结果）
motivation	string	场景发生的直接前因（可来自前文或隐含逻辑）
characters	array	主要出场人物
location	string	主要地点
time	string	具体时间（如“1969年秋，周日午后”）
key_event	string	本场景核心事件（一句话）
emotion	string	主导情绪（如“孤独/温暖/绝望”）
atmosphere	string	关键氛围描写（可选，若 include_atmosphere 为 false 则省略）


##示例
**输入**
source_text: 玄德引军出谷，行不数里，忽闻喊声大震，一彪军马从山坡后杀出，当先一员大将，乃曹仁也。玄德急回马，望西便走。曹仁随后赶来，幸得张飞杀到，截住曹仁，玄德方得脱身。
options: {"granularity": "medium", "focus": "full", "include_atmosphere": true}
