# Skill 3：宏大叙事织网者（Grand Narrative Weaver, S3）

## 功能描述
专为史诗级、多家族、跨地域的宏大叙事作品（如《史记》《三国志》《冰与火之歌》《指环王》《红楼梦》）设计。该 Skill 将全书内容整理成一份结构化的 **JSON 文件**，从**阅读流、绝对时间、人物命运、地理区域**四个维度彻底解构复杂叙事，帮助读者或 AI 系统理清“谁、何时、何地、为何”四大核心问题。

---

## 输入格式
用户需要提供以下信息：
- `work_title`：作品名称（用于 JSON 根键）。
- `main_factions_or_regions`（必填）：作品中的核心地理单元或政治/家族阵营（例如：魏/蜀/吴；史塔克家族/兰尼斯特家族；宁国府/荣国府等）。若不提供，AI 将根据场景切换自动识别（建议 3~6 个）。
- `main_characters`（可选）：主要人物名单。若不提供，AI 将根据叙事权重自动识别（建议 5~10 人）。
- `raw_text`：作品的完整文本（或分段粘贴，或上传文件）。

---

## 输出格式
**输出应为一份合法的 JSON 文件**，其顶级结构如下：

```json
{
  "work_title": "string",
  "generated_date": "ISO 8601 date string",
  "sections": {
    "reader_order": [ ... ],
    "chronological": [ ... ],
    "character_chronicles": { ... },
    "regional_chronicles": { ... }
  }
}

# 板块一：reader_order（原书阅读顺序内容分块概括）

类型：Array

每个元素为一个 object，描述原书一个连续片段（按卷/回/章或自然分隔）。

字段说明：

segment_id：唯一标识符，如 "S01"。

chapter_ref：对应的原书章节名或编号（如 "第一回" 或 "Chapter 1"）。

summary：该片段的概括性文字（保留插叙、倒叙、书信等，但注明类型）。

contains_flashback：布尔值，是否包含闪回。

contains_flashforward：布尔值，是否包含预叙或预言。

associated_characters：该片段中出现的人物列表（数组）。

associated_regions：该片段涉及的主要地理区域或势力（数组）。

# 板块二：chronological（严格绝对时间线 / 编年史）
类型：Array

每个元素为一个 object，描述一个不可再分的核心事件（政治军事行动、天灾、重大政变等）。

字段说明：

event_id：唯一标识符，如 "E001"。

time_label：该事件对应的客观时间描述（如 "建安五年" 或 "AC 298年"）。

time_rank：数字，表示整条时间轴上的排序（从 1 开始递增）。

summary：该事件的客观叙述（剥离主观情绪，只保留动作、决策、结果）。

participants：参与或涉及该事件的人物列表。

regions：该事件发生或影响的主要地理区域/势力（数组）。

uncertainty（可选）：若时间无法精确定位，此处注明推测依据，否则为 null。

# 板块三：character_chronicles（主要人物纪传 / 纪传体）
类型：Object

键为人物名称（字符串），值为该人物的视角条目数组。

每个条目为一个 object，字段包括：

subjective_time：该人物主观时间轴上的定位（例如 "赤壁之战前夕" 或 "守夜人总司令任期第一年"）。

event_summary：从该人物视角所见、所想、所经历的重要事件（允许主观色彩）。

objective_event_ref（可选）：若该内容可对应到 chronological 中的某事件，填写其 event_id，否则为 null。

# 板块四：regional_chronicles（地理区域 / 国别体记事）
类型：Object

键为地理区域或势力名称（字符串），值为该区域的时间线数组。

每个条目为一个 object，字段包括：

period_label：该段落对应的区域内部时期（如 "刘表治下（190-208）" 或 "五王之战期间"）。

summary：该时期本区域内发生的重要事件、统治更迭、边界变化等。

key_events：该区域内发生的标志性事件名称数组（如 ["官渡之战", "赤壁之战"]）。

rulers_or_governors（可选）：该时期的主要统治者或负责人列表。

跨区域事件处理原则：同一战争或政变若涉及多个区域，可在每个相关区域小节内均作简要提及，但需在 summary 末尾标注 （详见 [事件名称] 主条目），避免重复赘述。

核心逻辑与执行步骤
预处理与切分：按原书“卷/回/幕”切分段落，提取所有地名、人名、时间词。

建立地理数据库与空白年表：将用户提供的 main_factions_or_regions 作为顶层键，并识别各区域首次出现的时间。

板块一（reader_order）生成：直接压缩原文各段落，保留文学性顺序，并标记闪回、预叙等。

板块二（chronological）生成：将所有硬核事件（战争、外交、天灾、即位等）挂载到统一时间轴上，按先后排序。

板块三（character_chronicles）生成：按人物拆分所有涉及该人物的片段，重组为个人时间线（主观顺序）。

板块四（regional_chronicles）生成：按区域标签对所有事件进行二次聚类，并按区域内部时间线排序（若内部时间线混乱，可参考板块二的 time_rank 辅助排序）。

交叉引用（可选）：在板块三和板块四中，可适当添加 objective_event_ref 字段指向板块二的具体事件，增强数据联通性。

# 注意事项
动态领土变化：若同一区域在不同时期归属不同势力，应在 period_label 中清晰标明起止时间和政权归属（如 "曹魏治下（220-265）"）。

长途行军与迁移：人物穿行多个区域时，需在出发区域和到达区域分别记录“离开”和“抵达”事件。

架空纪年：若作品使用特殊历法（如《冰与火之歌》的“AC”纪年），时间标签直接沿用该体系，无需换算。

摘要语言：保持客观、凝练，聚焦于“谁、何时、何地、发生了什么”，避免文学评论。
